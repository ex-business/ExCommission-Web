# ExCommission-Web

独立 React 19 + TypeScript 5 前端，连接 ExCommission Go V1。沿用 v35 原型的业务导航与浅色蓝灰视觉；V1 标准优先。后端仓库保持独立。本项目不自动创建或推送远程仓库。

## 启动

本地 `.env` 已配置两套独立登录口令与后端沙箱引用。口令为 `WEB_OPERATOR_PASSWORD` / `WEB_APPROVER_PASSWORD`，仅在本机读取；不要提交或发送到日志。

```sh
docker compose up -d --build
```

访问 http://127.0.0.1:18180 ，选择业务申请人或独立审批人后输入对应本地口令。可运行 `node tools/local-login.mjs operator` 或 `node tools/local-login.mjs approver` 将对应口令复制到 macOS 剪贴板，不向终端显示。必须退出后重新登录另一身份；同一主体不能通过切换界面角色自审。

纯本机运行：`npm ci`、`npm run build`，再用 `BACKEND_URL=http://127.0.0.1:18080 BIND_HOST=127.0.0.1 npm start`。Docker 内后端通过 host.docker.internal:18080 访问。

## 模块

- `src/modules/plans`：方案配置与模板；`users`：用户来源；`agents`：代理关系与资格；`finance`：计算、账簿、结算、付款、审批、退款和风控；`reports`：查询与快照；`system`：连接、权限、目录和审计。
- `src/components`：布局、递归类型表单、结果表格；`src/auth`：登录会话；`src/lib`：请求、类型校验、资源索引、中文字段目录。
- `contracts/openapi.json`：V1 公共契约。59 项公开操作中 58 项具备管理页面，付款回调为受信渠道专用，不开放浏览器代签。
- `server`：同源会话与代理，不实现佣金业务，不访问数据库。资金与授权决定始终由 Go 后端执行。

## 使用

创建方案按基础路由、参与等级、收益规则、结算策略四步填写，完整表单校验通过后核对提交。读取草稿后可转试算，取得证明后申请发布。审批详情核对摘要与修订，由独立审批人作决定；批准后继续检查执行状态。

没有全量列表接口的资源按编号查询，浏览器索引只保存操作过的资源编号，不是全量业务列表。切换操作会丢弃未提交输入，提交结果在后端保留；请先完成当前表单。刷新或关闭浏览器不会自动重放命令。

写操作原输入重试保留原幂等键；修改输入才产生新键。对网络未知结果应先查询原资源，不创建新付款。审批过时先重读，不盲重试。原始响应可展开核对。UTC 时间显式填写 Z；金额保持字符串与币种最小单位，不自动换汇。

审计及祖先链分页携带原筛选与固定时点。报表按币种查看，缺收入或归因时显示服务端不可用原因。导出为固定快照，下载重新鉴权，过期响应如实呈现。

## 验证与维护

`npm test`：代理安全与协议边界。`npm run build`：TypeScript 严格检查和生产构建。页面验收工具与实际结果见 `tests/`、`docs/acceptance.md`。

停止仅执行本工程 `docker compose stop`，重启 `docker compose up -d`。回退切换本仓库提交并重建 web 镜像；不回退、删除或重置后端数据库。不要执行全局 Docker 清理。

## 生产边界

仅本地回环访问、双身份沙箱；没有真实身份源、业务来源、银行渠道或生产容量/SLO/RPO/RTO验收。沙箱付款成功不表示银行到账。本地口令与非持久化一小时会话不用于生产，生产需正式身份会话、TLS、密钥管理、可审查的连接与容量验收。
