# ExCommission-Web

图文说明：[工程职责、系统关系与操作流程](docs/工程说明.md)。

独立 React 19 + TypeScript 5 前端，连接 ExCommission Go V1。沿用 v35 原型的业务导航与浅色蓝灰视觉；V1 标准优先。后端仓库保持独立。本项目不自动创建或推送远程仓库。

## 启动

本地 `.env` 已配置两套独立登录口令与后端沙箱引用。口令为 `WEB_OPERATOR_PASSWORD` / `WEB_APPROVER_PASSWORD`，仅在本机读取；不要提交或发送到日志。

```sh
docker compose up -d --build
```

访问 http://127.0.0.1:18180 ，选择业务申请人或独立审批人后输入对应本地口令。可运行 `node tools/local-login.mjs operator` 或 `node tools/local-login.mjs approver` 将对应口令复制到 macOS 剪贴板，不向终端显示。必须退出后重新登录另一身份；同一主体不能通过切换界面角色自审。

纯本机运行：`npm ci`、`npm run build`，再用 `BACKEND_URL=http://127.0.0.1:18080 BIND_HOST=127.0.0.1 npm start`。Docker 内后端通过 host.docker.internal:18080 访问。

## 模块

- `src/modules/plans`：方案配置与模板；`users`：用户来源；`agents`：代理关系与资格；`finance`：计算、账簿、结算、付款、审批、退款和风控；`reports`：查询与快照；`system`：连接、权限、目录和审计。
- `src/components`：布局、递归类型表单、结果表格；`src/auth`：登录会话；`src/lib`：请求、类型校验、资源索引、中文字段目录。
- `contracts/openapi.json`：当前前端使用的V1契约子集。66 项操作中 65 项具备管理入口，付款回调为受信渠道专用，不开放浏览器代签。
- `server`：同源会话与代理，不实现佣金业务，不访问数据库。资金与授权决定始终由 Go 后端执行。

## 使用

创建方案按基础路由、参与等级、收益规则、结算策略四步填写，完整表单校验通过后核对提交。读取草稿后可转试算，取得证明后申请发布。审批详情核对摘要与修订，由独立审批人作决定；批准后继续检查执行状态。

没有全量列表接口的资源按编号查询，浏览器索引只保存操作过的资源编号，不是全量业务列表。切换操作会丢弃未提交输入，提交结果在后端保留；请先完成当前表单。刷新或关闭浏览器不会自动重放命令。

写操作原输入重试保留原幂等键；当前浏览器会话仅保存命令摘要和键，不保存载荷，刷新后重新输入原内容仍沿用原键。修改输入才产生新键。对网络未知结果应先查询原资源，不创建新付款。审批过时先重读，不盲重试。原始响应可展开核对。UTC 时间显式填写 Z；金额保持字符串与币种最小单位，不自动换汇。

审计及祖先链分页携带原筛选与固定时点。报表按币种查看，缺收入或归因时显示服务端不可用原因。导出为固定快照，下载重新鉴权，过期响应如实呈现。

## 验证与维护

`npm test`：代理安全与协议边界。`npm run build`：TypeScript 严格检查和生产构建。页面验收工具与实际结果见 `tests/`、`docs/acceptance.md`。

停止仅执行本工程 `docker compose stop`，重启 `docker compose up -d`。回退切换本仓库提交并重建 web 镜像；不回退、删除或重置后端数据库。不要执行全局 Docker 清理。

## 生产边界

仅本地回环访问、双身份沙箱；没有真实身份源、业务来源、银行渠道或生产容量/SLO/RPO/RTO验收。沙箱付款成功不表示银行到账。本地口令与非持久化一小时会话不用于生产，生产需正式身份会话、TLS、密钥管理、可审查的连接与容量验收。

## 佣金审核与派发

专用页面位于“结算与审核 → 佣金审核 → 佣金审核与派发”：可筛选分页、选择单笔/多笔审核、查看每项处理结果、填写备注；批准后准备本次金额的派发草稿，支持编辑/取消及批量提交。金额使用字符串和BigInt精确换算，不经浮点。草稿取消不删除佣金，已提交或未知付款不能伪造渠道撤单。

`node tools/commission-review-acceptance.mjs` 启动隔离临时页面服务并进行真实浏览器交互测试（模拟HTTP），结束自动停止测试进程。`tools/verify-review-contracts.mjs` 可校验后端脱敏HTTP证据；本次55个后端真实HTTP响应与25个成功请求体通过。后端MySQL资金闭环与浏览器模拟分别验收，不混称真实银行到账。

生产构建和10项测试通过；Docker引擎当前500，新后端/新代理的运行实例联部署尚未完成。浏览器现有服务可能仍使用旧接口允许清单与旧后端，不能据构建通过宣称新功能已经上线。

会员佣金：支持可信会员账号登录、本人结算列表及主动领取。待领取才显示领取按钮，处理中、已领取、取消、失败与核验异常均按后端状态展示；后台可选择会员领取或直接派发。会员登录需先在后端配置真实用户绑定，令牌不返回浏览器。运行 `node tools/member-claims-acceptance.mjs` 可验证会员页面交互。

会员PC/H5页面已提供推荐奖励、我的团队、收益与钱包、代理规则、分享链接/二维码和本人邀请确认。会员账号必须预先在后端可信绑定。运行 `node tools/member-portal-acceptance.mjs` 可验证两种屏幕宽度及二维码真实解码。当前Docker后端未更新时，新接口不可视为已在现有服务上线。

## 模拟会员项目身份来源

可选 `MEMBER_SOURCE_FILE` 指向不入库的私有 JSON，配置 `login_url`、`revoke_url`、`client_id`、`client_secret`、`local_sandbox`。身份接入位于 ex-member-sandbox 的独立回环端口。HTTP 必须显式启用本地沙箱且使用字面量回环地址；其他来源要求 HTTPS。不得把私有文件放入 dist 或浏览器配置。

会员选择“会员”身份，用模拟项目已注册邮箱和密码登录。BFF向来源认证后，必须再由佣金后端确认注册映射及 member:read 权限；来源令牌只存服务端会话，退出同时尝试撤销。配置来源后，失败不会回退另一套同名静态账号；不配置时保留原有会员登录。管理员登录保持原有方式。

`/?role=member` 仅预选登录身份，不建立或提升权限。模拟会员页可配置到该地址的入口，仍需同账号登录。启用后端 MEMBER_INVITATION_SOURCE 的注册适配器后，会员中心分享码与模拟注册页共用九位数字邀请码和 ic 参数，旧站点分享方式保持兼容。

【涉及其他业务】涉及共用BFF登录/退出、原管理员及会员会话、分享推广页面。19项测试、构建及真实浏览器PC/H5验证通过；奖励进度、计算器、多语言、批量领取与IP/设备策略未在本轮补齐，不能据此宣称完整原型页面已验收。

## 新版奖励领取可信上下文

会员 `POST /v1/me/affiliate/claims` 沿用既有登录、CSRF、契约和幂等键校验，再由 BFF 使用 `AFFILIATE_CLIENT_CONTEXT_KEY` 签名；此密钥须与后端一致且至少32字符，BFF 同时配置与后端一致的 `LOCAL_TENANT`、`LOCAL_APP`。所有值仅通过私有运行配置注入，不能进入 dist 或公开示例。未配置时领取不向后端转发，后端概览在未配置密钥时报告领取未开放。

签名绑定服务端会员身份、后端令牌摘要、方法、完整上游请求路径、正文摘要、幂等键、时间和实际 TCP 对端 IP。浏览器提供的 IP、转发头和签名均不采用；在反向代理环境中，当前记录的是代理连接地址，尚未接入受控代理的终端 IP 提取。
