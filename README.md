# ExCommission-Web

代理业务前端，提供运营管理后台和会员代理页面。规则计算、审批及账务由独立后端 [ExCommission](https://github.com/ex-business/ExCommission) 处理。

## 管理后台

配置代理规则和等级条件，完成试算、发布、结算审核及报表查询。

![方案条件配置页面](docs/images/conditions.jpg)

## 会员页面

查看邀请奖励、团队进度和佣金收益，分享邀请链接并领取已达标奖励。运营账号与会员账号分别登录。

## 列表分页

列表统一默认每页20条，支持20/50/100条；已有游标列表使用后端分页，配置和明细数组使用本地分页，编辑行保留输入。

## 外部业务接口经网关

设置 `EX_SERVICE_GATEWAY_CONFIG_FILE` 指向0600私有配置，示例见 `configs/external-gateway.example.json`。启用后业务请求只经固定网关，故障不直连、不重发写请求；既有会话/CSRF和内部服务发现保持。当前本地接入19486/19586，控制面Web与内部Go服务继续走内部通道。详细路由、验收和边界见相邻 `ex-service-gateway/docs/Web与内部服务接入.md`。

【涉及其他业务】公共登录及业务转发路径改变；已验证运营/会员登录、站点隔离、领取签名到参数校验及退出。尚未执行真实资金成功领取验收。

网关发现SDK使用vendor固定发布包及lock完整性校验，独立克隆无需相邻Router目录。


## 受信网关入口

启用 `WEB_ENTRY_KEY` 后，浏览器入口必须携带网关签署的来源证明；密钥仅配置在网关和该Web服务端，长度至少32，不进入仓库。证明绑定原始Host、路径、方法、正文、实际来源IP和时间，浏览器不能自行填写转发头绕过。

`WEB_PUBLIC_ORIGINS` 可配置固定HTTPS来源的JSON数组，例如 `["https://app.example.com"]`。只有入口证明校验通过后才接受该来源，并给会话Cookie增加Secure；保留原HTTP配置时，仍按原方式处理。外部Origin与内部监听端口分开，私有监听仅允许网关访问。

【涉及其他业务】影响本站登录来源、会话Cookie及来源IP。原业务角色、站点授权和CSRF继续校验；该接入不代表Web会话或数据库已多节点化。入口高可用配置参考 ex-service-gateway 的 `docs/入口高可用.md`。
