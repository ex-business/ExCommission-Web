# ExCommission-Web 工程说明

负责代理管理后台及会员代理页面。React 页面和 Node BFF 属于本工程；佣金计算、审批决定和账务结果由 ExCommission 后端处理。

## 系统关系

当前由五个独立工程协作，运营身份与会员身份分开管理，代理后台与运营中心不融合页面。

| 工程 | 主要负责 | 当前本地入口 | 数据和权限边界 |
|---|---|---|---|
| ExCommission | 佣金规则、代理关系、奖励、结算、审批、报表 | API `127.0.0.1:19286`；worker `19287` | 业务库、资金事务、幂等及业务授权 |
| ExCommission-Web | 代理后台和会员代理页面；同源 BFF | [19486](http://localhost:19486/) | 浏览器会话与转发；不直接决定资金结果 |
| ex-ops-identity | 运营账号认证、站点角色、会话及审计 | 身份 API `127.0.0.1:19587` | 独立运营库；不复用会员账号 |
| ex-ops-identity-web | 运营人员账号、角色和站点管理页面 | [19586](http://127.0.0.1:19586/) | 只转发运营管理白名单；不承载代理页面 |
| ex-member-sandbox | 模拟会员注册登录、邀请及可靠事件投递 | [19386](http://127.0.0.1:19386/)；身份 `19387` | 独立会员库；不是正式会员平台 |

本地目录 `ex-member-sandbox-identity` 对应远程仓库 `ex-business/ex-member-sandbox`，不是额外的第六个工程。以上端口是本次联调实例，不覆盖各工程示例配置的默认端口。

```text
Ops browser -> Ops Web :19586 -> Ops Identity :19587 -> Ops DB
                                      ^
                                      | verify account / site / roles
Admin browser -> Business Web :19486 --+--> ExCommission :19286 -> Business DB
Member browser -> Business Web :19486 -> Member Identity :19387 -> Member DB
                                             ^
Member registration :19386 -> signed outbox --+--> ExCommission
ExCommission worker :19287 -> calculation / settlement / delivery
```

运营身份服务只提供账号、站点和角色；每个业务系统自行映射业务权限。其他尚未接入的业务系统不能因此视为已自动接通。

## 页面与入口

| 左侧分组 | 主要操作 |
|---|---|
| 方案配置 | 创建/读取方案、修订草稿、可配置条件、试算发布、版本历史与回退 |
| 用户管理 | 查找用户、同步用户、查询同步结果 |
| 代理管理 | 代理关系、资格等级、目录、奖励开关及代理业务总表 |
| 结算与审核 | 佣金计算、账簿、结算、付款对账、审批、退款、风控及奖励 |
| 数据报表 | 收益/财务/成本类型查询；创建导出、详情和下载 |
| 系统管理 | 推荐返佣、已授权站点配置、站点代理、公共设置及审计等 |

六组原有菜单已恢复，身份接入不再隐藏原业务菜单。旧权限管理入口不用于管理运营账号；运营账号授权转至19586。会员本人操作需要会员身份。扩展接入目录及签名来源接口仅展示接入说明，不提供浏览器代提交表单。

## 登录与权限

```text
Staff login -> BFF -> Ops Identity -> private BFF session -> Business API
Member login -> BFF -> Member Identity -> member session -> Member business API
```

选择“运营账号”登录。BFF仅将本系统会话Cookie和白名单资料返回浏览器，不下发身份服务会话、后端令牌或签名密钥。登录身份不由界面选择“审批人”决定，角色来自真实站点授权。

切换站点后刷新页面。每个业务请求绑定页面已确认站点；旧标签页不匹配返回409并要求刷新，不能沿用旧表单提交新站点。退出只销毁本业务登录及其关联上游会话，不把19586页面融合进来。

## 配置与运行

Node.js22及以上；执行 `npm ci`、`npm run build`、`npm start`。服务端配置应通过本机私有环境加载。

| 配置 | 用途 |
|---|---|
| `BACKEND_URL` | 固定佣金API地址，本次为19286 |
| `BIND_HOST`、`PORT` | 本机监听，当前19486 |
| `OPS_IDENTITY_URL` | 固定运营身份API `http://127.0.0.1:19587` |
| `OPS_IDENTITY_ORIGIN` | 身份服务认可的Web来源 `http://127.0.0.1:19586` |
| `OPS_SITE_IDS` | 本业务允许接入的站点列表，例如1000、2000 |

会员来源、注册签名、来源事实和领取上下文相关密钥继续保存在服务端。配置运营身份后，运营登录失败不会退回旧共享密码。动态验证码是否要求由身份服务开关决定，当前默认关闭。

## 常用流程

1. 19586创建运营账号并授予站点角色。
2. 19486使用运营账号登录，确认右上角站点。
3. 原方案走“方案配置”；新增代理奖励规则走“系统管理 / 推荐返佣”。推荐返佣先点击读取配置再编辑。
4. 申请修改后由另一真实主体审批；发布结果和生效时间须继续核验。
5. 报表选择类型与筛选条件，导出创建后按原快照下载。

403先核对该站点角色；409先刷新并确认站点或版本；付款未知先查原付款单。页面展示入口不等于拥有操作权限。

## 验证与限制

24项Node测试及生产构建通过；浏览器已核验原等级条件表单与报表查询。BFF测试包含会话隐私、CSRF、切站CAS、撤权、旧业务转发及会员路径隔离。

【涉及其他业务】共用登录、代理转发及旧通用表单调用链已回归；会员余额和重复领取回归通过。未执行真实付款及逐页生产验收。
